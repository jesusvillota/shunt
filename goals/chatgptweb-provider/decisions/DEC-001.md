## Question and options

How should ChatGPT Web tool calls (run a command, edit a file) work for Codex through shunt?

- **A. Copy the repo's design (MCP connector + OpenAI tunnel).** ChatGPT calls tools itself through a custom MCP connector. Shunt would run the MCP server and relay each call into Codex's tool surface. Needs, per account: Developer Mode, a connector, a tunnel, an API key. The whole tool loop stays inside one web answer, so cost per turn is low. Rotation is hard because a turn is bound to one account's connector and tunnel.
- **B. Text protocol.** Shunt tells ChatGPT to write tool calls in a fixed, parseable format. Shunt returns normal `function_call` items to Codex. Codex runs the tool and sends the result in the next turn. Each turn resends the transcript to a fresh chat. No connector, no tunnel. Any account can serve any turn, so rotation is easy. Quality depends on the model following the format.
- **C. B first, A later only if B is too weak.**

Criteria: keeps shunt's rotation; Chat mode only; no new secrets; effort to build; tool quality; long-context cost; ban/abuse risk.

## Evidence

README of this goal (comparison table). Repo: `docs/architecture.md` and `docs/security-model.md` (miuuyy/codex-chatgpt-web). TASK-001's report `docs/notes/chatgptweb-survey.md`, section `Tool-call approaches`, adds facts after it is merged.

## Recommendation

Planner lean: **C (B first)**. B fits shunt's existing model (self-contained turns, pool rotation, no per-account tunnel) and is the smaller build. A keeps the tool loop inside one answer and is better for long tool-heavy turns, but its per-account connector and tunnel conflict with the owner's rotation requirement. Revisit after the M-1 live smoke and after M-2 measurements. This is a recommendation only; the owner decides.

Accepted by jesusvillota on 2026-10-23: C: B first (text protocol), A only if M-1/M-2 show B too weak
