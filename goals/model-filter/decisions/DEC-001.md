## Question and options

Which parameters should the headless agent use to rank the free OpenCode models, and how should the ranking be produced?

Constraints: the free set changes often; the ranking runs only when the owner presses `r`; the result must be reproducible enough to explain; the owner can edit the criteria without a code change.

- **A. One overall judgement.** Ask for "the best order for agentic coding work". Simple, but the reasons are hidden and two runs can differ a lot.
- **B. Fixed rubric, order from the agent.** Give a list of parameters and ask the agent for the final order. The reasons are visible, but the weighting is still the agent's.
- **C. Rubric with scores, shunt computes the order.** The agent returns a 0 to 10 score per parameter per model, and shunt sorts by a weighted sum kept in the criteria file. The weights are the owner's, and two runs differ only when the scores differ.

Candidate parameters (the owner chooses which to keep and the weights): general intelligence, coding ability, tool use and agentic reliability, instruction following, long-context handling, speed, and recent availability (how often the model hit rate limits).

## Evidence

Not collected yet. The ranking agent can search the web for current benchmarks. `docs/notes/opencode-log-format.md` (TASK-002) will give real availability data from the opencode log.

## Recommendation

Option C. It keeps the human in charge of the weights, shows the score behind every position, and lets the owner tune the result by editing one file. Start with these parameters and weights: coding ability 30%, tool use and agentic reliability 25%, general intelligence 20%, instruction following 10%, speed 10%, availability 5%. This is a proposal; the owner decides.
